# 领域对象设计

## DDD中的领域对象类型

在领域驱动设计中，领域对象主要分为三种类型：
1. **聚合根（Aggregate Root）**
2. **实体（Entity）**
3. **值对象（Value Object）**

## 聚合根（Aggregate Root）

### 概念
聚合根是聚合的入口点，负责维护聚合内部的一致性边界。外部只能通过聚合根来访问和修改聚合内部的实体。

### 聚合根的职责
- 维护聚合内部的数据一致性
- 封装业务规则
- 发布领域事件
- 控制对外暴露的接口

### 项目中的聚合根

#### 1. Book聚合根（Catalog上下文）

```java
package library.catalog.domain;

@Entity
public class Book {
    @EmbeddedId
    private BookId id;
    private String title;
    @Embedded
    @AttributeOverride(name = "value", column = @Column(name = "isbn"))
    private Isbn isbn;

    Book() {
        // JPA需要无参构造函数
    }

    public Book(String title, Isbn isbn) {
        // 业务规则验证
        Assert.notNull(title, "title must not be null");
        Assert.notNull(isbn, "isbn must not be null");

        this.id = new BookId();
        this.title = title;
        this.isbn = isbn;
    }

    public BookId getId() {
        return id;
    }

    public String getTitle() {
        return title;
    }

    public Isbn getIsbn() {
        return isbn;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        Book book = (Book) o;
        return Objects.equals(id, book.id);
    }

    @Override
    public int hashCode() {
        return Objects.hashCode(id);
    }
}
```

**特点：**
- 使用`@Entity`注解标记为JPA实体
- 使用`@EmbeddedId`嵌入主键值对象
- 构造函数中包含业务规则验证
- 重写`equals`和`hashCode`，基于ID比较

#### 2. Copy聚合根（Catalog上下文）

```java
package library.catalog.domain;

@Entity
public class Copy {
    @EmbeddedId
    private CopyId id;
    @Embedded
    @AttributeOverride(name = "id", column = @Column(name = "book_id"))
    private BookId bookId;
    @Embedded
    private BarCode barCode;
    private boolean available;

    Copy() {
        // JPA需要无参构造函数
    }

    public Copy(BookId bookId, BarCode barCode) {
        // 业务规则验证
        Assert.notNull(bookId, "bookId must not be null");
        Assert.notNull(barCode, "barCode must not be null");

        this.id = new CopyId();
        this.bookId = bookId;
        this.barCode = barCode;
        this.available = true;  // 新副本默认可借
    }

    public void makeUnavailable() {
        this.available = false;
    }

    public void makeAvailable() {
        this.available = true;
    }
}
```

**特点：**
- 封装状态变更逻辑：`makeUnavailable()`、`makeAvailable()`
- 新副本默认状态为可借阅
- 与Book聚合通过BookId关联，不直接引用Book对象

#### 3. Loan聚合根（Lending上下文）

```java
package library.lending.domain;

@Entity
public class Loan extends AbstractAggregateRoot<Loan> {
    @EmbeddedId
    private LoanId loanId;
    @Embedded
    @AttributeOverride(name = "id", column = @Column(name = "copy_id"))
    private CopyId copyId;
    @Embedded
    @AttributeOverride(name = "id", column = @Column(name = "user_id"))
    private UserId userId;
    private LocalDateTime createdAt;
    private LocalDate expectedReturnDate;
    private LocalDateTime returnedAt;

    @Version
    private Long version;

    Loan() {
    }

    public Loan(CopyId copyId, UserId userId, LoanRepository loanRepository) {
        // 业务规则验证
        Assert.notNull(copyId, "copyId must not be null");
        Assert.notNull(userId, "userId must not be null");

        // 验证副本是否可借
        Assert.isTrue(loanRepository.isAvailable(copyId),
            "copy with id = " + copyId + " is not available");

        this.loanId = new LoanId();
        this.copyId = copyId;
        this.userId = userId;
        this.createdAt = LocalDateTime.now();
        this.expectedReturnDate = LocalDate.now().plusDays(30);  // 30天借阅期限

        // 发布领域事件
        this.registerEvent(new LoanCreated(this.copyId));
    }

    public void returned() {
        this.returnedAt = LocalDateTime.now();

        // 检查是否逾期
        if (this.returnedAt.isAfter(expectedReturnDate.atStartOfDay())) {
            // 计算逾期费用（业务逻辑）
            // TODO: 实现费用计算
        }

        // 发布领域事件
        this.registerEvent(new LoanClosed(this.copyId));
    }
}
```

**特点：**
- 继承`AbstractAggregateRoot<Loan>`，支持领域事件发布
- 使用`@Version`注解实现乐观锁
- 构造函数中验证业务规则
- 封装复杂业务逻辑：借阅、归还、逾期检查
- 状态变更时发布领域事件

### 聚合设计原则

1. **一致性边界**：聚合内部的所有修改必须保持一致性
2. **事务边界**：一个聚合在一个事务中完成
3. **小聚合**：聚合应该尽量小，避免包含太多实体
4. **通过ID引用其他聚合**：不直接引用其他聚合的对象，只引用ID

## 实体（Entity）

### 概念
实体是具有唯一标识的对象，即使其属性完全相同，如果ID不同，它们就是不同的实体。

### 特点
- 有唯一标识
- 有生命周期
- 可以变更状态
- 通过标识判断相等性

### 项目中的实体

在本项目中，聚合根本身就是实体（如Book、Copy、Loan），它们都有唯一的ID。

```java
// 实体的相等性判断
@Override
public boolean equals(Object o) {
    if (this == o) return true;
    if (o == null || getClass() != o.getClass()) return false;
    Book book = (Book) o;
    return Objects.equals(id, book.id);  // 基于ID判断相等
}
```

## 值对象（Value Object）

### 概念
值对象是通过属性值来标识的对象，没有唯一的标识。两个值对象如果所有属性都相同，它们就是相等的。

### 特点
- 不可变（Immutable）
- 没有唯一标识
- 通过属性值判断相等性
- 可以自由替换和共享

### 项目中的值对象

#### 1. Isbn（国际标准书号）

```java
package library.catalog.domain;

import org.apache.commons.validator.routines.ISBNValidator;

public record Isbn(String value) {
    private static final ISBNValidator VALIDATOR = new ISBNValidator();

    public Isbn {
        // 构造时验证ISBN格式
        if (!VALIDATOR.isValid(value)) {
            throw new IllegalArgumentException("invalid isbn: " + value);
        }
    }
}
```

**特点：**
- 使用Java `record`实现，自动不可变
- 构造函数中进行业务规则验证
- 值对象的验证逻辑封装在对象内部

#### 2. BookId（书籍ID）

```java
package library.catalog.domain;

import org.springframework.util.Assert;

import java.util.UUID;

public record BookId(UUID id) {
    public BookId {
        Assert.notNull(id, "id must not be null");
    }

    public BookId() {
        this(UUID.randomUUID());
    }
}
```

**特点：**
- 类型安全的ID，避免使用原始类型
- 构造函数验证ID不为null
- 提供无参构造函数自动生成UUID

### 值对象的好处

#### 1. 类型安全
```java
// 不好的做法：使用原始类型
public void addBook(String bookId, String copyId) {
    // 容易混淆参数顺序
}

// 好的做法：使用值对象
public void addBook(BookId bookId, CopyId copyId) {
    // 编译时就能发现类型错误
}
```

#### 2. 业务规则封装
```java
// 验证逻辑封装在值对象内部
Isbn isbn = new Isbn("978-3-16-148410-0");  // 自动验证格式
// 无需在外部重复验证逻辑
```

#### 3. 不可变性保证
```java
// record自动实现不可变性
Isbn isbn = new Isbn("978-3-16-148410-0");
// isbn.value = "xxx";  // 编译错误，无法修改
```

#### 4. 表达力强
```java
// 代码意图清晰
if (copyId.equals(anotherCopyId)) {
    // 明确是在比较副本ID
}
```

## 领域对象设计最佳实践

### 1. 使用构造函数验证业务规则
```java
public Loan(CopyId copyId, UserId userId, LoanRepository loanRepository) {
    Assert.notNull(copyId, "copyId must not be null");
    Assert.notNull(userId, "userId must not be null");
    Assert.isTrue(loanRepository.isAvailable(copyId), "copy is not available");
    // ...
}
```

### 2. 封装状态变更
```java
public class Copy {
    private boolean available;

    public void makeUnavailable() {
        this.available = false;
    }

    public void makeAvailable() {
        this.available = true;
    }
    // 不要暴露setter，而是提供有业务意义的方法
}
```

### 3. 值对象不可变
```java
// 使用Java record实现不可变值对象
public record Isbn(String value) {
    public Isbn {
        if (!isValid(value)) {
            throw new IllegalArgumentException();
        }
    }
}
```

### 4. 实体基于ID判断相等性
```java
@Override
public boolean equals(Object o) {
    if (this == o) return true;
    if (o == null || getClass() != o.getClass()) return false;

}
```

### 5. 聚合根通过ID引用其他聚合
